# AIWGuard VMS — ROI 침범 감시 웹 VMS (Jetson Orin Nano / 윈도우 추론 프로그램 겸용)

추론 소스가 TCP로 전송하는 좌표를 받아 화면에 설정한 ROI(관심영역)와의
침범률(%)을 계산하고, 임계값을 넘으면 이벤트 팝업과 "침수발생" 경고음을 울리는 웹 기반 VMS입니다.
최대 128채널의 RTSP 영상을 등록해 1~36분할 PIP 화면으로 감시할 수 있습니다.

추론 소스는 **Jetson Orin Nano 보드와 윈도우용 추론 프로그램을 동시에** 쓸 수 있습니다.
메시지 포맷(NDJSON)은 양쪽이 동일하고 연결 방향만 다르며, 두 방향 모두 지원합니다:

| 모드 | 방향 | 쓰는 경우 |
|---|---|---|
| **접속 (VMS→소스)** | VMS가 소스의 IP:Port로 접속 | 소스가 TCP 서버 — Jetson 보드(기본 192.168.30.110:7070), 윈도우 `AI W-Guard`(DATA 모드, 기본 **9100**) |
| **수신 대기 (소스→VMS)** | VMS가 포트를 열고 대기, 소스가 접속해 전송 | 소스가 TCP 클라이언트인 경우(기본 포트 7100) |

> 윈도우 `AI W-Guard`를 쓸 때는 그 프로그램의 `config.cfg`에 `SERVICE_MODE = DATA`와
> `DATA_SEND_POLYGONS = true`가 설정되어 있어야 합니다. 폴리곤을 보내지 않으면 VMS가 자기 ROI로
> 침범률을 계산할 수 없어 항상 0%가 됩니다.

설정 > **TCP 연결** 탭에서 소스마다 모드를 고르며, 두 종류를 동시에 여러 개 등록할 수 있습니다.
수신 대기 포트 하나에 여러 대의 윈도우 PC가 동시에 접속해도 됩니다.
자세한 내용은 [docs/PROTOCOL.md](docs/PROTOCOL.md) 참고.

## 빠른 시작

```bash
npm install
npm start
# http://localhost:8080 접속
```

브라우저 접속 즉시 "🔊 모니터링 시작" 버튼을 한 번 눌러야 알람 사운드(사이렌/TTS)가 재생됩니다
(브라우저 자동재생 정책).

## 1. 실제 소스 없이 알람 파이프라인 먼저 체험하기

실제 보드/윈도우 프로그램이 준비되기 전에도 핵심 기능(TCP 수신 → ROI 침범률 계산 → 팝업/사운드 알람)을
바로 확인할 수 있습니다. 두 연결 방향 각각의 모의 송신기가 있습니다.

```bash
# Jetson 포맷 + 접속(VMS→소스) 모드 검증: 보드처럼 TCP 서버로 대기
node scripts/mockJetsonServer.js 7070 1

# 윈도우 AI W-Guard 포맷 검증: hello + detection(폴리곤 포함)을 그대로 흉내
node scripts/mockWinGuardServer.js 9100 4

# 수신 대기(소스→VMS) 모드 검증: 소스가 VMS로 접속해 밀어넣는 경우
node scripts/mockWindowsClient.js 127.0.0.1 7100 1
```

1. 웹 UI 설정(⚙) > **채널/RTSP** 탭에서 채널 하나를 추가하고 **"cam ID"에 `1`** 을 입력
   (모의 송신기가 보내는 `cam` 번호와 일치해야 좌표가 그 채널로 들어갑니다)
2. 설정 > **TCP 연결** 탭에서
   - 접속 모드를 테스트하려면: 모드 "접속 (VMS→소스)", 대상 `127.0.0.1:7070`
   - 수신 대기 모드를 테스트하려면: 기본 등록된 "윈도우 추론 수신 대기"(0.0.0.0:7100) 항목의 **사용**을 체크
3. 그리드에서 해당 채널 타일의 "＋ROI" 버튼으로 화면 중앙 부근에 폴리곤을 그려 저장(임계값 예: 30%)
4. 모의 송신기가 원을 그리며 움직이는 가상 객체를 전송 → ROI와 겹칠 때 침범률이 올라가고
   임계값을 넘으면 우측 상단에 경고 팝업 + 사이렌/TTS "침수 발생" 음성이 재생됩니다.

실제 Jetson 보드 연동 시에는 TCP 연결 대상을 `192.168.30.110:7070`(기본값, 이미 등록됨)으로 두면 되고,
윈도우 추론 프로그램은 VMS의 `<VMS IP>:7100`으로 접속해 같은 NDJSON을 보내면 됩니다
(다른 PC에서 접속한다면 **윈도우 방화벽에서 7100 포트를 열어야** 합니다 — 설치 마법사의 방화벽 태스크에 포함).
메시지 포맷은 [docs/PROTOCOL.md](docs/PROTOCOL.md) 참고.

소스가 우리가 가정한 NDJSON 포맷과 다른 데이터를 보내는지 확인하려면 `TCP_DEBUG=1` 환경변수로 실행하면
수신되는 원본 바이트를 그대로 콘솔에 찍어줍니다(두 모드 모두, 접속별/상대별로 구분해 출력):

```powershell
$env:TCP_DEBUG = "1"; node server/index.js
```

## 2. 실제 RTSP 영상 재생 (MediaMTX 연동) — 검증 완료

브라우저는 RTSP를 직접 재생할 수 없어 [MediaMTX](https://github.com/bluenviron/mediamtx)를 통해
WebRTC(WHEP)로 저지연 변환합니다. **MediaMTX는 이 프로젝트와 별도 프로세스로 직접 실행해야 합니다.**
(2026-08-27, 실제 RTSP 4채널로 WHEP 영상 재생까지 end-to-end 검증 완료)

1. https://github.com/bluenviron/mediamtx/releases 에서 Windows용 바이너리 다운로드
   (`mediamtx.exe` 하나만 있으면 됨 — 이미 다른 도구가 설치해 둔 mediamtx.exe가 있다면 재사용 가능)
2. `mediamtx/mediamtx.yml.example` 을 `mediamtx/mediamtx.yml` 로 복사 (이 파일은 `.gitignore` 대상 — 환경별로 다름)
   - `api: yes`, `webrtc: yes` 필수. 이미 다른 RTSP 서버가 8554 등을 쓰고 있다면 `rtsp: no`로 꺼서 포트 충돌을 피할 것
   - **MediaMTX v1.19+**: 기본적으로 MoQ 리스너(`:8892`)가 켜져 있어 포트 충돌이 날 수 있음 → `moq: no` 추가
3. `mediamtx.exe mediamtx.yml` 실행 (작업 디렉터리를 `mediamtx/` 로 맞추면 상대경로 그대로 사용 가능)
   - 정상 기동 로그 예: `[API] started with listener on :9997`, `[WebRTC] started with listeners on :8889 ...`
4. 웹 UI 설정 > **MediaMTX** 탭에서 Host/API Port/WHEP Port가 실행 중인 MediaMTX와 일치하는지 확인 후 저장
   (저장 시 서버가 등록된 모든 채널의 path를 즉시 재동기화합니다 — MediaMTX를 채널 등록 이후에 띄웠어도 이 저장 한 번으로 따라잡음)
5. 채널/RTSP 탭에서 채널을 추가·저장하면 서버가 자동으로 MediaMTX에 path를 동기화하고,
   그리드 타일이 WHEP으로 해당 채널 영상을 재생합니다. `sourceOnDemand: yes`라서 실제로 화면에 표시되는
   순간(WHEP 요청 시점)에 MediaMTX가 RTSP 소스를 당겨오기 시작하므로 첫 프레임까지 수 초 걸릴 수 있습니다.

MediaMTX가 꺼져 있어도 나머지 기능(ROI 설정, TCP 좌표 수신, 알람)은 정상 동작하며,
영상 타일에는 "영상 연결 실패" 안내만 표시됩니다.

문제가 있으면 `http://<mediamtx host>:9997/v3/paths/list` 로 각 채널 path의 `ready`/`online` 상태를 확인하세요.

## 3. 다른 PC에 설치하기 (Windows 설치 패키지 빌드) — 검증 완료

다른 Windows PC에서도 Node.js 설치 없이 바로 쓸 수 있도록 단일 설치 파일(.exe)을 만들 수 있습니다.
서버는 [Node.js SEA(Single Executable Application)](https://nodejs.org/api/single-executable-applications.html)로
번들되어 대상 PC에 Node.js가 없어도 동작하며, MediaMTX 바이너리도 함께 동봉되어 폐쇄망(사내망)에서도
설치 후 바로 사용할 수 있습니다.

### 빌드하는 법 (이 저장소를 만든 PC 등, 빌드용 PC에서 1회)

1. [Inno Setup 6](https://jrsoftware.org/isinfo.php) 설치 (설치 마법사 컴파일러, winget: `winget install JRSoftware.InnoSetup`)
2. `build/vendor/mediamtx/mediamtx.exe`를 준비 — [build/vendor/mediamtx/README.md](build/vendor/mediamtx/README.md) 참고
   (용량이 커서 저장소에는 포함되어 있지 않습니다)
3. `npm install` (esbuild, postject 등 빌드 도구 포함)
4. `npm run build:installer` (내부적으로 `node build/build-server.mjs` → esbuild+Node SEA로 서버를 단일 exe로 번들 →
   Inno Setup으로 설치 마법사 컴파일, 순서로 진행됩니다)
5. 결과물: `build/out/AIWGuardVMS-Setup-<version>.exe` — 이 파일 하나만 다른 PC에 전달하면 됩니다.

### 설치 패키지 만들기
- ./build/build-all.ps1

### 버전 바꾸기

빌드하기 전에 아래 **두 파일의 버전을 같은 값으로** 직접 고칩니다. 두 값은 서로 연결되어 있지 않아서 하나만 바꾸면
설치 파일 이름과 프로그램 안에 표시되는 버전이 달라집니다.

| 파일 | 고칠 곳 | 쓰이는 곳 |
|---|---|---|
| `package.json` | `"version": "0.3.2"` | 설정 > Help > 프로그램 정보의 버전 표시(`v0.3.2`). 개발 모드는 서버가 이 파일을 직접 읽고, 배포 빌드는 `build/build-server.mjs`가 이 값을 exe에 넣는다 |
| `installer/aiwguard-vms.iss` | `#define MyAppVersion "0.3.2"` | 설치 마법사와 Windows "앱 및 기능"에 보이는 버전, 설치 파일 이름 `AIWGuardVMS-Setup-<version>.exe` |

- 버전 형식은 `주.부.수` (예: `0.3.2`)이며, 앞에 `v`는 붙이지 않습니다(화면에 표시할 때 자동으로 붙습니다).
- `package-lock.json`의 버전은 직접 고치지 않아도 됩니다 — 다음 `npm install` 때 `package.json` 값으로 맞춰집니다.
- 바꾼 뒤 설치 패키지를 다시 빌드해야 exe와 설치 파일에 반영됩니다(`npm run rebuild`).

### 클린 빌드

```
npm run clean      # build/out/ 만 삭제 (전부 빌드가 다시 만드는 파일)
npm run rebuild    # clean + build:installer
```

- `npm run clean`은 `build/out/`에서 실행 중인 `aiwguard-vms.exe`가 있으면 **그것만** 종료합니다
  (설치본 `C:\Program Files\AIWGuardVMS\aiwguard-vms.exe`는 다른 파일이라 건드리지 않으므로 운영 중인
  인스턴스는 계속 돕니다). Windows가 실행 중인 exe를 잠가서 빌드가 실패하는 것을 막기 위한 것입니다.
- **삭제하지 않는 것**(빌드가 다시 만들어주지 않음): `build/vendor/mediamtx/`(동봉용 바이너리),
  `pwd.dat`(지우면 다음 빌드가 **기본 비밀번호로 새로 만들어** exe에 심는 비밀번호가 바뀝니다), `data/`.
- 의존성까지 완전히 새로 받으려면: `npm run clean; Remove-Item -Recurse -Force node_modules; npm ci; npm run build:installer`
- 빌드 후 `build/out/aiwguard-vms.exe`의 `LastWriteTime`이 갱신됐는지 확인하세요.

### 설치 패키지에 포함되는 것

- `aiwguard-vms.exe` — Node.js 런타임이 통째로 내장된 서버 실행파일 (대상 PC에 Node.js 불필요)
- `public/` — 웹 UI 정적 파일
- `mediamtx/mediamtx.exe` + `mediamtx.yml` — RTSP→WebRTC 변환 (동봉, 별도 다운로드 불필요. MIT 라이선스,
  `mediamtx/LICENSE-MediaMTX.txt`에 원문 포함)
- Start 메뉴 바로가기(서버 시작 / MediaMTX 시작 / 웹 화면 열기 / 제거), 선택 항목: 바탕화면 아이콘,
  Windows 시작 시 자동 실행, 방화벽 포트(8080, 9997, 8889, 8888) 자동 허용
- 설치 후 생성되는 `data/`(설정·이벤트로그) 폴더는 프로그램 제거 시에도 삭제되지 않습니다

### 대상 PC에서 사용하는 법

`AIWGuardVMS-Setup-<version>.exe` 실행 → 설치 마법사 진행(관리자 권한 필요) → 설치 완료 후 자동으로
MediaMTX + VMS 서버가 시작되고, PC의 실제 IP 주소(예: `http://192.168.0.10:8080`, 다른 PC에서도 접속 가능)로
브라우저가 열립니다. 이후에는 Start 메뉴의 "AIWGuard VMS 서버 시작"과 "MediaMTX 시작 (RTSP 영상 변환)"으로
필요할 때마다 켤 수 있습니다. 두 구성요소 모두 **최소화된 창**으로 실행되어 작업표시줄에만 남습니다 —
끄려면 작업표시줄에서 해당 창을 열어 닫으면 됩니다(또는 작업 관리자에서 `aiwguard-vms.exe` / `mediamtx.exe` 종료).

## 4. 주요 메뉴

- **레이아웃**: 상단 1/4/8/16/36 분할 전환 (8분할 = 왼쪽 위 큰 화면 1 + 작은 화면 7, 작은 화면에 마우스를 올려 "크게보기"로 큰 화면 채널 선택 — 지금 보는 화면에서만 적용되고 채널 순서는 바뀌지 않아,
  다른 페이지로 넘어가거나 분할을 바꾸면 원래 순서로 돌아갑니다)
  - 등록된 채널은 **모두 자동 배치**되고, 화면 페이지 탭은 채널 수와 분할 수로 **자동 생성**됩니다
    (예: 12채널 → 4분할 화면1~3, 8분할 화면1~2, 16/36분할 화면1). 분할을 바꾸면 항상 화면1부터 보입니다.
  - 영상은 각 칸을 **여백 없이 꽉 채웁니다**(칸 비율에 맞춰 늘림). 칸과 영상의 비율이 다르면 영상이 가로 또는 세로로
    늘어나 보이지만, 화면 가장자리가 잘리지 않아 영상 전체와 ROI가 항상 다 보입니다. ROI 선도 늘어난 영상에 맞춰 그려집니다.
  - 36분할에서는 타일이 작아 **＋ROI / ROI수정 / ROI삭제 버튼이 타일에 마우스를 올렸을 때만** 보이며,
    ROI 추가·수정을 누르면 해당 채널이 **확대 보기로 먼저 열린 뒤** 편집이 시작됩니다(작은 타일에서는 편집 폼이 잘리므로).
  - 36분할은 브라우저가 영상 30여 개를 동시에 디코딩하므로, 카메라가 지원하면 채널 RTSP 주소를
    **서브스트림(저해상도)** 으로 등록하는 것을 권장합니다.
  - v0.2.5에만 있던 32분할은 제거되었습니다. 32분할로 저장돼 있던 화면은 시작할 때 36분할로 바뀝니다.
  - 예전 버전의 수동 화면 페이지("+"로 추가)는 자동 페이지로 바뀌었습니다. 기존 페이지에 배정돼 있던 채널이
    그 순서대로 앞에 오고, 배정하지 않았던 채널은 채널 목록 순서대로 뒤에 붙습니다.
- **채널 순서 바꾸기**: 좌측 채널 목록 클릭 후 원하는 타일 클릭, 또는 드래그&드롭 — 그 자리에 있던 채널과 서로 자리가 바뀝니다
- **사용자분할**: 분할 버튼 맨 오른쪽. 8분할과 같은 모양(큰 화면 1 + 작은 화면 7)으로 **직접 고른 채널만** 고른 순서대로 보여줍니다.
  - 좌측 채널 목록을 클릭하면 화면에 추가되고(목록에 고른 순서 번호 표시), 다시 클릭하면 빠집니다. 타일 제목줄의 ×로도 뺄 수 있습니다.
  - 채널을 타일로 끌어다 놓으면 그 자리에 들어갑니다(이미 고른 채널이면 자리 맞바꿈, 새 채널이면 끼워 넣고 뒤 채널은 한 칸씩 밀림).
  - 고른 채널이 8개를 넘으면 화면 페이지(화면2, 화면3…)가 자동으로 늘어납니다. "크게보기"도 8분할과 같이 쓸 수 있습니다.
  - 고른 목록은 서버에 저장되어 다른 분할로 갔다 와도, 재시작해도 그대로입니다. 다른 분할의 채널 순서에는 영향을 주지 않습니다.
- **ROI 설정**: 타일의 "＋ROI"로 폴리곤 그리기(클릭=정점 추가, 되돌리기=마지막 점 취소,
  더블클릭/완료=폴리곤 닫기) → 이름/판정 기준/알람 라벨 저장
- **기존 ROI 수정**: 타일의 **"ROI수정"** 버튼(ROI가 없으면 비활성, 여러 개면 목록에서 선택) 또는
  영상 위의 **ROI 칩 클릭** → 임계값(침범률 %/물높이 m), 눈금 기준선, 이름, 알람 라벨을 고치거나
  정점을 드래그해 모양 수정/삭제
- **ROI 판정 기준 2가지**(ROI마다 따로 선택): **침범률(%)** 또는 **물높이(m)**. 아래 "5. 물높이(m) 기준 ROI" 참고
- **ROI 삭제**: 개별 ROI 삭제(칩 편집창) / 채널별 전체삭제("ROI삭제" 버튼) / 전체 채널 ROI 모두 삭제(설정 > 채널 관리)
- **TCP 연결 설정**: 설정 > TCP 연결 — 소스별로 모드(접속/수신 대기) 선택, IP·Port 다중 등록,
  실시간 상태 표시(수신 대기 모드는 현재 접속 대수까지)
- **채널/RTSP 관리**: 최대 128개, 제목/RTSP 주소/channel_id/cam ID/소스 관리
  (여러 소스가 같은 cam 번호를 쓸 때는 채널의 "소스"를 지정해 구분)
- **채널 한 번에 추가/삭제**(설정 > 채널/RTSP 탭):
  - **여러 채널 한 번에 추가**: 버튼을 누르면 열리는 입력칸에 RTSP 주소를 **한 줄에 하나씩** 붙여넣으면 한 번에 등록됩니다.
    `제목, RTSP주소, cam ID` 순서로 적을 수도 있고(쉼표 또는 탭 구분), 주소만 적으면 제목(`채널5`…)과
    cam ID(시작 번호부터 1씩 증가)는 자동으로 채워집니다. `#`으로 시작하는 줄과 빈 줄은 무시합니다.
    추가하기 전에 해석 결과를 미리 보여주며, **한 줄이라도 잘못되어 있으면 아무것도 등록하지 않고** 몇 번째 줄이 왜 틀렸는지 알려줍니다.
  - **선택 삭제 / 선택 사용 / 선택 해제**: 행 왼쪽 네모로 여러 채널을 고른 뒤(Shift+클릭 = 범위 선택, 머리글 네모 = 전체 선택)
    한 번에 삭제하거나 사용 여부를 바꿉니다. 삭제는 그 채널의 ROI와 화면 배치까지 함께 정리합니다.
  - **⚠ 전체 채널 삭제**: 등록된 채널을 전부 지웁니다. 되돌릴 수 없으므로 확인창에 `삭제`를 직접 입력해야 실행됩니다.
  - 한 줄씩 추가할 때는 표 맨 아래 줄에서 **Enter**로도 추가되며, 추가 후 커서가 채널명 칸으로 돌아와 이어서 입력할 수 있습니다.
- **실시간 수신 현황**(설정 > 채널/RTSP 탭 상단): 각 소스가 **지금 실제로 보내고 있는 cam 번호**를
  칩으로 보여주고, 어느 채널로도 매핑되지 않아 버려지는 번호는 노란색으로 경고합니다. 채널 표의
  cam ID 칸에도 `● 수신중 / ○ 수신없음`이 표시됩니다.
  cam ID가 어긋나면 좌표는 아무 오류 없이 조용히 버려지므로(화면만 안 나옴) 원인을 찾기 매우 어려운데,
  이 표시로 설정값과 실제 수신값을 바로 대조할 수 있습니다.
  > 실제 사례: 윈도우 AI W-Guard는 화면 이름이 `T5~T8`이고 카메라가 cam5~cam8이어도, 채널 번호는
  > `RTSP_URL1..4` 순번대로 **1~4**를 보냅니다. cam ID를 5~8로 넣으면 4개 채널이 통째로 먹통이 됩니다.
- **알람 설정**: 사이렌/TTS on-off, 볼륨, 사운드 반복 간격(초, 확인 전까지), 반복 경고 팝업 주기(분, 확인 후에도
  침수가 계속되면 재알림), 쿨다운, 히스테리시스, 커스텀 mp3 업로드, 탐지 오버레이 표시 여부
- **이벤트 로그**: 최근 알람 이력 확인/확인(Ack)/CSV 내보내기
- **화면 테마**: 설정 > **화면 테마** 탭에서 "클래식 다크 / 딥 오션 / 하이드로 차트" 중 선택. 아래 "화면 테마" 참고
- **알람 팝업 복원**: 침수가 이미 진행 중일 때 브라우저를 새로 열거나 새로고침해도, 아직 확인(Ack)하지 않은
  알람 팝업이 화면 우측에 그대로 다시 뜹니다(서버가 접속 시 진행 중인 알람 목록을 함께 내려줌).
  이게 없으면 알람은 "발생하는 순간"에만 전송되므로 새로고침한 화면은 침수 중에도 팝업이 하나도 없게 됩니다.
- **설정 모달**: 입력 중 실수로 닫히지 않도록 바깥 배경 클릭으로는 닫히지 않으며, 우측 상단 × 버튼으로만 닫습니다.
  **제목 표시줄("⚙ 설정")을 끌어 창을 원하는 위치로 옮길 수 있습니다** — 뒤에 가려진 영상이나 ROI를
  보면서 설정을 바꿀 때 유용합니다. 옮긴 위치는 브라우저에 기억되며, 제목 표시줄을 **더블클릭하면
  가운데로 되돌아갑니다**.
  창은 **화면 경계를 넘지 못합니다** — 상하좌우 어느 쪽으로 끌어도 화면 안에 완전히 머무르며,
  브라우저 창 크기를 바꾸거나 확대/축소해도, 탭을 바꿔 모달 높이가 달라져도 경계 안으로 자동 보정됩니다.

### 장시간 운영을 위한 자동 복구 동작 (v0.2.9)

관제 화면은 며칠씩 켜 두므로, 사람이 새로고침하지 않아도 스스로 회복하도록 되어 있습니다.

- **영상 자동 재연결**: 영상 연결이 실패하거나 끊기면(MediaMTX 재시작, 카메라 전원 차단, 네트워크 흔들림) 타일에
  사유를 표시하고 **3초 → 6초 → … → 30초** 간격으로 계속 다시 붙입니다. 연결은 살아 있는데 **30초간 새 프레임이
  없으면**(카메라/RTSP 쪽 문제) 정지로 보고 다시 붙입니다. 재연결 중에는 멈춘 마지막 장면을 실시간으로
  오해하지 않도록 영상을 내리고 안내 문구를 띄웁니다.
- **추론 소스 연결 감시**: TCP keepalive로 보드 전원이 꺼지거나 케이블이 빠진 경우(FIN 없이 사라짐)도 수십 초
  안에 알아채고 재접속합니다(예전에는 상태등이 초록인 채 좌표만 안 오는 상태가 될 수 있었음).
- **브라우저 연결 정리**: 서버가 30초마다 WebSocket ping을 보내 응답 없는(죽은) 브라우저 연결을 끊습니다.
  느린 브라우저(백그라운드 탭 등)에 프레임이 밀리면 실시간 프레임은 건너뛰고 알람/설정 변경만 보냅니다.
- **서버 재접속 시 영상 유지**: VMS 서버가 재시작되어 브라우저가 다시 붙을 때, 보고 있던 화면 배치가 그대로면
  타일을 다시 만들지 않습니다(영상은 브라우저↔MediaMTX 직결이라 서버와 무관하게 계속 재생됨).
- **런타임 오류 격리**: 기동 후에 생기는 예기치 못한 오류(프레임 하나의 처리 오류 등)는 콘솔에 표시만 하고
  서버는 계속 실행됩니다. 기동 자체가 실패하는 오류(포트 충돌, 폴더 권한)는 예전처럼 원인을 보여주고 종료합니다.
- **전송량 절약**: "탐지된 물/도로 영역 표시"가 꺼져 있을 때(기본)는 서버가 탐지 폴리곤을 브라우저로 보내지
  않고 개수만 보냅니다(침범률 계산은 서버에서 이미 끝났으므로 판정에는 영향 없음). 좌표는 소수 4자리로
  정리해 보냅니다(4K 해상도에서도 0.4px 미만 차이).
- **이벤트 로그 회전**: `events.log`가 20MB를 넘으면 `events.log.1`로 밀어내고 새로 씁니다(직전 세대 하나 보관).

## 5. 물높이(m) 기준 ROI — 교각 수위표 눈금 읽기

교각에 붙은 **수위표(눈금판)** 를 보고 "물이 몇 미터까지 찼는가"로 알람을 울리는 방식입니다.
기존 침범률(%) 방식은 그대로 유지되며, **ROI를 만들 때 둘 중 하나를 고릅니다.**

| | 침범률(%) | 물높이(m) |
|---|---|---|
| 판정값 | ROI 면적 중 물이 덮은 비율 | ROI 안에서 읽어낸 수면의 눈금값 |
| 알람 조건 | 침범률 ≥ 임계값(%) | 수위 ≥ 임계 물높이(m) |
| 알람창 표시 | `87.5%` | `1.35m` (음성 안내도 "수위 1.35 미터") |
| 쓰는 곳 | 도로·둔치처럼 "얼마나 잠겼나"가 중요한 화면 | 교각에 수위표가 있는 화면 |

### 설정 방법

1. 수위표가 보이는 채널 타일에서 **＋ROI** → 교각의 **눈금 구간을 따라 세로로 길쭉하게** 폴리곤을 그립니다.
   - **수위표(교각) 폭 안쪽**에 그려야 합니다. 교각 옆 강물까지 물면 그 부분은 위쪽까지 전부 물이라
     수면선을 찾을 수 없습니다.
   - 감시하려는 최고 수위까지 덮도록 위로 넉넉히 그리세요.
2. 판정 기준에서 **물높이(m)** 를 선택하면 ROI 위에 **연두색 기준선 두 개**가 나타납니다.
   이 선을 **실제로 숫자가 보이는 눈금 위로 끌어다 놓고**, 그 자리의 눈금값을 입력합니다.
   - **하단 기준선 눈금(m)**: 아래쪽 기준선이 놓인 눈금값 (= 계산의 출발점이 되는 **최하값**)
   - **상단 기준선 눈금(m)**: 위쪽 기준선이 놓인 눈금값
   - **임계 물높이(m)**: 이 수위 이상이면 침수 이벤트 발생
   > **물높이 = 하단 기준선의 눈금값 + 하단 기준선에서 수면선까지의 높이**로 계산됩니다.
   > 두 기준선의 간격이 "몇 픽셀 = 몇 미터"인지를 알려주는 자 역할을 합니다.
3. **"현재 측정값"** 에 판독값이 실시간으로 표시됩니다(괄호 안은 평활화 전 값). 기준선을 끌거나 눈금값을
   고치면 **저장 전에도 즉시** 값과 화면의 선이 따라 움직이므로, 실제 영상의 눈금과 대조하며 맞출 수 있습니다.
   맞으면 **저장**을 누르세요(끌어 놓은 위치는 저장해야 반영됩니다).
4. 저장 후 화면에는 **빨간 점선 = 임계 수위**, **실선 = 지금 읽은 수면선**(임계 초과 시 빨간색)이 그려집니다.

> **기준선을 ROI 경계가 아니라 눈금 위에 놓는 이유**: ROI의 아래쪽은 대개 **물에 잠겨 눈금이 안 보입니다.**
> 그 지점의 눈금값은 사람이 알 수 없어 어림짐작하게 되고, 그러면 **표시되는 수위가 실제 눈금과 어긋납니다.**
> 눈에 보이는 눈금 두 곳에 선을 맞추는 것이 정확한 유일한 방법입니다.
> (기준선을 옮기지 않은 예전 설정은 ROI의 위/아래 경계를 기준선으로 간주해 그대로 동작합니다.)

### 어떻게 눈금을 읽는가

추론 소스가 보내는 **water 폴리곤의 위쪽 경계(= 수면선)** 가 ROI 안에서 어디에 있는지를 찾아,
두 기준선이 만든 기준자로 미터로 환산합니다. ROI를 가로 띠 64개로 나눠 **아래에서 위로** 훑으며
물로 찬 구간이 끊기는 지점을 수면선으로 잡습니다(위에서부터 찾지 않는 이유: 수면 위 물보라나
젖은 얼룩이 물로 잡히면 수위가 과대평가되기 때문). 구현: [server/roi/waterLevel.js](server/roi/waterLevel.js)

> **숫자를 OCR로 읽지 않는 이유**: 이 서버에는 영상 프레임이 들어오지 않습니다(추론 소스는 폴리곤만
> TCP로 보내고, 영상은 브라우저가 MediaMTX에서 직접 받습니다). 게다가 수면 근처의 숫자는 물에 잠기거나
> 물보라·야간 적외선으로 뭉개져 가장 읽기 어려운 부분입니다. 반면 수면선의 위치는 세그멘테이션 결과에
> 이미 선명하게 들어 있어(실측: 눈금판 폭 안에서 한 띠 만에 0%→100%로 전환), 기준자만 한 번 맞춰 주면
> 눈금 사이값까지 연속으로 읽어냅니다.

### 흔들림 다루기 (중요)

실제 하천은 파도 때문에 수면선이 초 단위로 출렁입니다(실측 예: 30초 동안 0.55~0.98m).
그대로 쓰면 임계값 근처에서 알람이 깜빡이므로 두 가지 설정으로 다룹니다 — **설정 > 알람 설정**:

- **물높이 평활화(초)** (기본 10): 최근 이 시간 동안 읽은 값들의 **중앙값**을 판정에 씁니다.
  크게 잡을수록 안정적이지만 수위 상승 감지가 그만큼 늦어집니다. 0이면 평활화하지 않습니다.
- **히스테리시스(m, 물높이 ROI)** (기본 0.1): 알람이 울린 뒤 이만큼 더 내려가야 해제됩니다.

### 한계

- 눈금값 ↔ 화면 세로 위치를 **직선(1차식)으로 근사**합니다. 카메라가 수위표를 매우 비스듬히 내려다보면
  두 기준선에서 멀어질수록 오차가 커지므로, **기준선 두 개를 최대한 넓게(감시 구간을 감싸도록)** 놓으세요.
- 수면이 ROI가 덮는 범위를 벗어나면 그 바깥의 실제 수위는 볼 수 없으므로 `< 0.42m` / `≥ 1.86m` 처럼
  부등호로 표시됩니다. 감시하려는 최고 수위까지 ROI가 덮도록 그리세요.
- 카메라가 움직이면(바람·재설치) 기준자가 어긋납니다. 화면이 틀어졌다면 ROI를 다시 맞춰야 합니다.

## 6. 유속 표시 (유속 서비스 연동, v0.3.1~)

ROI 안의 **수면 유속과 방향**을 표시합니다. AI W-Guard 가 보내는 물 폴리곤에는 유속 정보가 없으므로, 추론 서버에서
**별도로 도는 유속 서비스**(`flow_service/`, 기본 포트 7200)가 영상에서 직접 광류를 계산해 보내 줍니다. 침수 감지
엔진과는 독립된 프로그램이라 켜고 끄거나 멈춰도 침수 알람에는 영향이 없습니다. 설치·운영은
[flow_service/README.md](flow_service/README.md)를 보세요.

연결 방법:
1. 설정 > **TCP 연결**에서 소스 추가 — 모드 "접속", IP(추론 서버), Port `7200`.
2. 그 행의 **번호 기준**을 AI W-Guard 소스로 지정 — 유속 서비스는 AI W-Guard 와 같은 채널 번호를 보내므로 같은 채널에 붙습니다.
3. 해당 채널에 ROI 를 그리면 ROI 마다 `유속 50px/s (51/52칸) ↗` 가 표시됩니다(괄호 = ROI 안 믿을 수 있는 칸 / 전체 칸).
   설정 > 알람 설정 > **유속 화살표를 화면에 표시**를 켜면 칸마다 "1초 동안 움직이는 거리"만큼의 화살표도 그립니다.

보정 전의 표시값은 **화면상 속도(px/s)이지 실제 m/s 가 아닙니다.** 비스듬한 카메라는 같은 물살도 화면 위쪽(먼 곳)이
느려 보입니다(실측: 같은 하천 근경 50px/s, 원경 11px/s). 실제 m/s 는 아래 **유속 보정**을 하면 나옵니다.

### 유속 보정 (m/s 환산, v0.3.2~)

수면 높이의 **기준점 4~8개**의 화면 위치와 실제 위치를 알려 주면, 화면과 수면 사이의 원근 관계(호모그래피)를 계산해
칸마다 실제 수면 속도(m/s)로 바꿉니다. 선 하나에 실제 길이를 주는 방식은 원근 때문에 선에서 멀어질수록 틀려서 쓰지 않습니다
(가상 카메라 시험: 선 방식 −46~−90%, 기준점 방식 0.00%, 현실적 잡음(화면 1px·좌표 2cm)에서도 −0.7~+2.1%).

1. 타일 제목줄의 **유속보정**을 누릅니다(36분할이면 확대 보기로 먼저 열림).
2. 영상에서 **수면 높이(수위선 근처)의 표식**을 클릭해 P1, P2… 를 찍습니다. 끌어서 옮길 수 있고, 입력창은 ◀▶ 로 반대쪽으로 옮깁니다.
   ROI 를 둘러싸도록 넓게 흩어진 점을 고르고, 세 점이 한 줄에 서지 않게 합니다.
3. 실제 위치를 입력합니다 — 둘 중 하나:
   - **좌표 입력**: 점마다 X, Y(m). 측량(GNSS·토탈스테이션) 좌표를 그대로 넣어도 되고 원점·방향은 자유입니다.
     **5~6개를 권장**합니다 — 남는 점으로 입력 오차를 검산해 "검산 오차 평균/최대"를 보여 줍니다.
   - **줄자 거리(점 4개)**: 네 변(P1–P2, P2–P3, P3–P4, P4–P1)과 대각선 2개(P1–P3, P2–P4)의 거리(m). 화면에 잴 변(실선)과
     대각선(점선)이 그려집니다. 6개 중 하나는 검산에 쓰여, 줄자 값끼리 맞지 않으면 알려 줍니다.
4. 계산되면 **실제 수면 위 격자**(1m·5m 등)가 영상에 겹쳐 그려집니다. 격자가 수면과 둑에 반듯하게 깔리는지 확인하고 **저장**합니다.
   점 순서를 바꿔 적었거나(P3 에 P4 좌표) 한 줄로 늘어선 점, 지평선 너머로 계산되는 입력은 이유와 함께 거부됩니다.

보정 후:
- ROI 유속 표시가 `유속 1.23m/s (51/52칸) ↗` 로 바뀝니다. ROI 가 기준점 범위(노란 점선) 밖이면 `보정범위 밖`이 붙습니다(외삽이라 덜 정확).
- ROI 의 판정 기준을 **유속(m/s)** 로 하면 임계 유속 이상일 때 알람이 울립니다(알람 설정의 **유속 평활화(초)** 동안의 중앙값으로 판정,
  해제는 **히스테리시스(m/s)** 만큼 내려가야 함). 알람 팝업·이벤트 로그·CSV·음성 안내("유속 초당 1.6 미터")에 m/s 가 남습니다.
- 유속 ROI 는 보정이 없어도 저장은 되며, 그동안은 `보정 전`으로 표시되고 알람이 울리지 않습니다.

주의:
- **수위가 기준점 높이에서 벗어나면 오차가 생깁니다.** 카메라가 수면 위 5m 일 때 수위가 0.5m 오르면 약 +11%, 1m 면 +25%.
  기준점은 평소 수위 근처에 두세요.
- 카메라가 돌거나(PTZ) 다시 설치되면 보정을 다시 해야 합니다.
- 표면 유속입니다. 유량 산정용 평균 유속은 보통 표면 유속 × 0.85 안팎이며, 설치 후 부자나 유속계로 한 번 대조하기를 권장합니다.
- 유속 결과가 5초 넘게 안 오면 화살표를 지우고 `유속 - (수신 없음)`으로 바뀝니다(멈춘 값을 실시간으로 오해하지 않도록).
  유속 알람은 결과가 다시 들어올 때까지 상태를 바꾸지 않습니다.
- 믿을 수 있는 칸 기준(`flowSettings.fbMin`=0.8, `rMin`=0.7)은 config.json 에서 바꿀 수 있습니다. 폭포·맑은 여울처럼
  수면 무늬가 흘러가지 않는 장면은 이 기준에 걸려 `유속 - (믿을 칸 없음)`이 됩니다.
- 모의 유속 소스로 시험하려면 `node scripts/mockFlowServer.js 7200 3` — 정답 유속을 아는 가상 카메라 영상의 결과를 보내고,
  보정에 쓸 기준점을 시작할 때 출력합니다.

  파일 맨 아래에 `html[data-theme="<id>"]` 접두사를 붙인 배치 규칙 절을 추가하면 됩니다(JS 변경 불필요).

## 설정 백업 / 복원

설정(⚙) > **백업** 탭의 **💾 설정 파일 내보내기**를 누르면 `aiwguard-config-v<버전>-<날짜>-<시각>.json` 파일이 내려받아집니다.

- 들어가는 것: 채널·RTSP 주소, ROI(침범률/물높이/유속), 채널 유속 보정값, TCP 연결, 알람 설정, 화면 분할·채널 순서, MediaMTX 설정
- 들어가지 않는 것: 이벤트 기록(`events.log`), 사용자 경보음 파일(`alarms\` 폴더 — 쓰고 있으면 백업 탭에 안내가 뜹니다)
- 파일에는 카메라 RTSP 주소(아이디/비밀번호 포함)가 그대로 들어 있으니 안전한 곳에 보관하세요.

설정이 저장되는 곳(설치본): **`C:\ProgramData\AIWGuardVMS\`** (숨김 폴더 — 탐색기 주소창에 직접 입력)

| 파일 | 내용 |
|---|---|
| `config.json` | 모든 설정 (내보내기 파일과 내용이 같음) |
| `alarms\` | 사용자 경보음(mp3) |
| `events.log` | 이벤트 기록 |

**복원 방법** (새 PC 또는 재설치 후)
1. AIWGuard VMS를 설치합니다.
2. **VMS를 종료합니다**(서버·MediaMTX 콘솔 창 닫기). 켜 둔 채로 복사하면 프로그램이 기억하고 있던 설정으로 다시 덮어씁니다.
3. 백업 파일 이름을 `config.json`으로 바꿔 `C:\ProgramData\AIWGuardVMS\`에 복사합니다(덮어쓰기). 사용자 경보음을 쓰던 경우 `alarms` 폴더도 같이 복사합니다.
4. VMS를 다시 실행합니다. 이전 버전에서 만든 백업이면 시작할 때 자동으로 새 형식으로 바뀝니다.

복사한 파일이 깨져 있어 읽지 못하면 기본 설정으로 시작하고, 원래 파일은 지우지 않고 같은 폴더에 `config.broken-<날짜>.json`으로 보관합니다.
제거(언인스톨)해도 이 폴더는 지워지지 않으므로, 같은 PC에서 재설치만 하는 경우에는 복원할 필요가 없습니다.

## 개발자 모드 (자세한 설명 팁 표시)

설정 화면의 각 항목에 대한 **자세한 설명은 평소에는 숨겨져 있습니다**(화면을 간결하게 유지하기 위함).
설명을 보려면 개발자 모드를 켜세요.

1. 설정(⚙) > **Help** 탭을 엽니다.
2. **버전 번호(예 `v0.2.0`)를 연속 5번 클릭**하면 비밀번호 입력창이 나타납니다. (2초 안에 이어서 눌러야 합니다)
3. 비밀번호를 입력하면 개발자 모드가 켜지고, 설정 화면 곳곳의 설명이 표시됩니다.
4. 끄려면 Help 탭의 "개발자 모드 끄기" 버튼을 누릅니다.

개발자 모드 상태는 **브라우저별로 저장**됩니다 — 한 명이 켜도 다른 운영자 화면은 그대로입니다.
비밀번호 확인은 전적으로 서버에서 하며, 비밀번호도 해시도 브라우저로 내려가지 않습니다.
연속 5회 틀리면 30초간 잠깁니다.

**단, 실시간 수신 현황의 cam 번호 칩과 미매핑 경고, 채널 표의 `● 수신중` 표시처럼 "지금 상태를
알려주는 정보"는 개발자 모드와 무관하게 항상 보입니다.** 숨겨지는 것은 설명문뿐입니다.

### 비밀번호 변경

기본 비밀번호는 `admin1357!!` 이며, **저장소 루트의 `pwd.dat`** 첫 줄에 평문으로 들어 있습니다
(파일이 없으면 빌드 시 기본값으로 자동 생성됩니다).

- **개발 모드**(`node server/index.js`): `pwd.dat`를 고치면 **서버 재시작 없이 즉시** 반영됩니다.
- **배포본**: 빌드가 `pwd.dat`를 읽어 **SHA-256 해시만 exe 안에 심습니다.** `pwd.dat` 자체는 설치
  패키지에 포함되지 않으므로, 배포본에는 평문 비밀번호가 어디에도 남지 않습니다
  (빌드가 산출물을 직접 검사해서 평문이 섞이면 빌드를 실패시킵니다).
  비밀번호를 바꾸려면 `pwd.dat`를 고치고 다시 빌드하세요.
- 재빌드 없이 설치된 PC의 비밀번호만 바꾸고 싶다면, `aiwguard-vms.exe` **옆에 `pwd.dat`를 두면**
  그 값이 내장 해시보다 우선합니다(평문이 그 PC에 남는다는 점은 감안하세요).

> `pwd.dat`는 `.gitignore` 대상입니다 — 평문 비밀번호를 저장소에 커밋하지 마세요.
